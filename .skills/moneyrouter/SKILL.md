# /MONEYROUTER

## Mission

Determine where the next dollar and next founder-hour should go without falling in love with a project, asset, narrative, technology, or previous decision.

## Loop

DISCOVER → VERIFY → MONEY PATH → COMPARE → TEST → MEASURE → COMPOUND / KILL

## DISCOVER

Enumerate realistic lanes. Discovery never authorizes spending.

## VERIFY

Classify evidence as VERIFIED, INFERRED, UNKNOWN, or BLOCKED. Prefer exact-head code, CI, runtime/Playwright receipts, payments, invoices, contracts, connected finance/commerce evidence, and direct customer actions.

## MONEY PATH

Require payer, offer, price, unit cost, delivery time, acquisition path, conversion evidence, repeatability, ownership, margin, and time to cash.

If payer + offer + price are not explicit, return DISCOVER.

## COMPARE

Compare expected net dollars, probability, repeatability, ownership, compounding value, capital velocity, cash required, founder hours, reversibility, dependency risk, and opportunity cost. Do not fake precision.

## WATCHER

Return BLOCK if the test touches protected cash, exceeds the experiment ceiling, has unbounded downside, depends on borrowing/leverage/loss-chasing, lacks rollback, uses stale evidence, or tries to scale from one lucky event.

## TEST

Every test requires hypothesis, max cash, max hours, action, pass condition, fail condition, stop condition, rollback, and proof required.

Prefer sale before build, manual fulfillment before automation, one customer before audience scaling, and one integration before architecture expansion.

## MEASURE

Capture revenue, cost, gross margin, founder hours, conversion, delivery success, refunds, repeat purchase, acquisition cost, time to cash, and failure reason.

## COMPOUND

COMPOUND requires protected cash intact, verified evidence, successful fulfillment, positive economics, repeatability, no unresolved critical failure, and at least two independent complete money cycles.

Scale one bounded step, then re-measure.

## KILL

KILL or pause when failure thresholds are reached, the money path is disproved, economics stay negative, another opportunity dominates, or the underlying assumption is falsified. Preserve reusable assets; killing the bet does not require deleting code.

## Fingerprints and continuity

Each run must emit:

- verified evidence IDs
- continuity cookie hash
- previous cookie hash when available
- deterministic decision fingerprint
- explicit rollback
- explicit stop condition

Evidence changes must change the fingerprint.

## SleepWealth authority boundary

This skill is non-authorizing decision support. It must never grant spending, brokerage, wallet, signing, transfer, funding, or live-execution authority. Repository-local approval, risk, broker, and authority controls outrank this skill.

## Hard truth rules

Deployment != revenue.
Usage != revenue.
Revenue != profit.
Followers != demand.
A customer saying yes != payment.
Payment != repeatability.
Valuation != liquid wealth.
AI confidence != evidence.
Founder attachment != strategic value.
